## 第一幕 · 为什么需要（3 页）

### P1 封面
- 标题：AI售后服务平台 —— 让海外消费者的每一次售后，自己走完
- 副标题：扫码 / 邮件发起 · AI 多语言首响 · 品牌方—工厂—经销商一个后台协作 · 客户全程可追踪
- 配图：三端拼图（H5 手机帧、追踪页手机帧、后台 PC 帧）

### P2 出海售后今天是怎么跑的
- 标题：一条客诉，14 封邮件，21 天，三家公司接力
- 要点：真实案例 FWT-61（F-C20，德国消费者 → 品牌售后 → 贸易对接 → 工厂）横向时间线：技术问答 2.5 天、备件确认 5 天（地址重复输入 3 次、工厂反问"要不要 20 号件"）、发货到拿到运单 4 天、消费者反馈靠人"明天没消息就催"
- 要点：问题不在哪一方不努力，而在于信息散在邮箱里、没有人盯着时限、每一环都要人翻译和转述
- 配图：原生形状画的 21 天时间线，四个卡点标红

### P3 我们把这条链路做成一个平台
- 标题：消费者一端、品牌方一端、工厂与经销商一端，中间是 AI 智能体
- 要点：三端一引擎——消费者端（扫码 H5 / 邮件 / 追踪页）、品牌方后台（PC 网页）、工厂与经销商按邀请登录同一后台只看自己那一份
- 要点：AI 做五件事：识别语言与产品、匹配知识库给出回复、判断该不该转人、盯时限与运单、把三方的话翻译并转述
- 要点：不改变海外用户发邮件的习惯，不装 App，不换邮箱
- 配图：总览架构图（原生形状）+ 三端缩略截图

## 第二幕 · 消费者侧全流程（9 页）

### P4 分幕页
- 两条入口（扫码、邮件）+ 一个追踪页：发起 → AI 处理与人工接力 → 追踪到解决

### P5 入口一：设备上一张固定二维码
- 标题：扫开就是售后窗口，不用装 App、不用注册
- 要点：不做"一物一码"——同型号一张码即可，也可按批次 / 按供应商分码；可下载 SVG / PNG 直接印刷
- 要点：扫码落地页：型号已识别、说明语言可选、两个动作"开始售后 / 看说明书"
- 配图：后台二维码卡片（含真实二维码）+ H5 落地页手机帧

### P6 H5 四步走廊
- 标题：选语言 → 拍标签 → 确认设备 → 开始咨询，四屏完成
- 要点：中文 / English / Deutsch / Español / Français / Svenska / Italiano 七种语言
- 要点：拍标签识别型号与序列号 → 自动关联订单、批次、分销商与保修状态；"标签看不清？直接咨询"保证不走死路
- 配图：四个手机帧并排（选语言 / 拍标签 / 标签确认 / 对话开场）

### P7 H5 对话：工单先建立，再开始聊
- 标题：客户还没打字，品牌方后台已经有这张工单
- 要点：进入对话即建单，顶部工单卡片写明"工单已建立 · 已抄送人工"，客户知道有人兜底
- 要点：AI 基于产品知识库回答：给步骤和视频、必要时追问（最多两轮）、涉及钢缆 / 锁扣等安全件直接转人工、符合规则的小件当场承诺补发
- 要点：客户说"还是不行"不会被反复套话，直接转售后工程师；结尾留邮箱 + 评分
- 配图：三个手机帧（对话开场 / 安全件转人工 / 收尾评分）

### P8 入口二：客户照常发邮件，AI 先读
- 标题：接管品牌售后邮箱，每封来信十步自动处理
- 要点：流水线：识别语言 → 识别产品 / 序列号 → 匹配订单 → 检索知识库 → 置信度对阈值 → 硬规则检查（安全件 / 退款 / 负面情绪 / B 端客户）→ 同批次聚集 → 合并到已有线程 → 决策 → 建工单
- 要点：决策三档：置信度够 → 用客户的语言直接回复；差一点 → 追问细节；不够或触发规则 → 转品牌方售后并附 AI 解析摘要
- 要点：客户回信自动判定：说"解决了"自动关单；"谢谢，但还是报 E07"不会被误关；关单 7 天内再来信自动重开
- 配图：后台"模拟新邮件进入"逐步面板截图（德语钢缆邮件走到"安全件转人工"）

### P9 AI 之后的三级接力
- 标题：AI → 品牌方售后 → 工厂，每一级都有时限
- 要点：状态机：AI处理中 → 修复指导中（先教客户自修，2 天跟进窗口）→ 待品牌方售后（4 小时）→ 已升级工厂（24 小时）→ 已解决；超时自动标红进"需要你的决定"
- 要点：修复优先：能自修的先给指引，没修好再转寄件，避免一上来就发备件
- 要点：承诺寄件：50 美元以内的小件按设置自动承诺并扣库存；超过的进品牌方确认
- 配图：原生形状状态流转图 + 工单列表 SLA 超时标红局部截图

### P10 客户追踪页：卡在谁手里、承诺什么时候，客户自己能看
- 标题：邮件里一个链接，客户不用再写"请问进度如何"
- 要点：状态横幅：现在在谁手里 + 一个宽承诺时间，超时自动改为"正在加急"
- 要点：一个邮箱名下多张工单自动分组（进行中 / 已解决）；中 / 英 / 德三语界面；一键回复自动带工单号；说明书入口
- 配图：追踪页列表帧 + 详情顶部帧

### P11 进度轨道与对客投影
- 标题：每一步下面一句话，客户只看到该看的
- 要点：进度轨道：建单 → 首次回复 → 转工程师 / 升级工厂 → 承诺发出 → 已发出 → 运单号（可复制）→ 签收 → 已解决，每步一句情况概括
- 要点：对客投影：工厂原文、内部批注、系统动作一律不出现；只投影给客户的内容
- 配图：轨道 + 寄件卡手机帧（FWT-61 客户视角）与后台同一工单时间线并排对照

### P12 消费者侧端到端一页
- 标题：从扫码 / 来信到解决评价，客户只做三件事
- 要点：泳道图：客户 / AI / 品牌方 / 工厂，客户泳道只有"发起、按指引操作或回复、评价"
- 要点：两个典型走向：A 跑带偏移（AI 直接解决，当天关单）；B 钢缆磨损（安全件 → 人工 → 工厂确认 → 寄件 → 签收）
- 配图：原生形状泳道图

## 第三幕 · 三方后台：协作与知识库（14 页）

### P13 分幕页
- 一个后台、三种身份、按订单关系决定能看什么

### P14 登录与角色：按订单邀请，按关系可见
- 标题：品牌方开通后台，工厂和经销商凭邀请进来，只看自己的订单
- 要点：三种角色：品牌方管理员（全量 + 唯一对客）、工厂销售（自己供货订单的工单、批次、库存，客户信息脱敏）、分销商（自己订单范围内的工单与订单，可标"门店已处理"）
- 要点：邀请制：按订单邀请接口人，接受后自动成为该订单（或该工厂全部订单）成员；撤销接口人，名下工单自动退回品牌方
- 要点：左侧菜单四组：工作台 / 产品与知识 / 协作与经营 / 配置；不同角色看到的菜单不同
- 配图：三个身份的侧栏并排（同一后台切换身份）

### P15 智能体首页：先看"需要你的决定"，再用一句话办事
- 标题：登录第一屏不是报表，是今天必须由你拍板的事
- 要点："需要你的决定"自动汇总：待售后、SLA 超时、等你确认补发、已发货没运单号、质量事件待验证、AI 建议升级工厂、工厂已回复待放行、说明书待审核、订单缺工厂接口人、邀请未接受
- 要点：自然语言直接执行："把今天的新工单汇总给我"、"给 SM-900 生成德法说明书"、"邀请青岛迈动的陈工做工厂接口人"、"把置信度阈值调到 80"——都是真实执行
- 配图：智能体首页整屏 + 一次"汇总"对话结果截图

### P16 工单处理：列表
- 标题：所有渠道的客诉在一张表里，筛得动、导得出
- 要点：按状态 / 渠道（邮件、扫码H5、代客录入）/ 产品 / 语种 / 批次筛选，搜索，导出 CSV；状态与 SLA 实时计算
- 要点："模拟新邮件进入"与"代客户录入"走同一条流水线
- 配图：工单列表整屏

### P17 工单详情：一张工单里装下整个案子
- 标题：对话、子问题、寄件、质量事件，不再散在 14 封邮件里
- 要点：完整时间线（客户原文 + AI 翻译 + 内部批注分层）、AI 起草回复可改可"换一种说法"、升级工厂、标记解决、确认补发（自动扣库存）、补录序列号
- 要点：一封来信拆成多条子问题，各带核销清单与负责人，互不阻塞；寄件记录件号、承诺日、发运、运单号，发货 24 小时没运单号自动催办；质量事件（CAPA）工厂提交验证、品牌方确认后才关闭
- 配图：FWT-61 工单抽屉（时间线 + 子问题 + 寄件 + CAPA），两张截图拼接

### P18 三方协作：升级到工厂这一步，AI 怎么接
- 标题：品牌方点"升级"，AI 自己找到该订单的工厂接口人
- 要点：解析链：工单 → 订单 → 该订单的工厂接口人；已激活 → 指派并通知；待接受 → 指派并催促；没有接口人 → 不允许升级完成，弹出带这张工单的邀请
- 要点：工厂回复进"待放行"，品牌方确认后 AI 翻译成客户语言发出——品牌方始终是唯一对客窗口
- 要点：AI 发现同批次聚集只给建议，不自动升级；分销商可标"门店已处理"，不参与升级链
- 配图：升级弹窗（找到接口人）+ 升级被拦下弹出邀请（两张）

### P19 工厂与分销商登录后看到什么
- 标题：各看各的，但在同一条线上
- 要点：工厂销售（宁波力健 · 李工）：工单（客户脱敏为语言区、序列号与批次、AI 摘要）、自己供应的批次与客诉率、备件库存、回复给品牌方放行、不能关单
- 要点：分销商（NordicGym · Erik）：菜单只剩智能体、工单处理、订单与协作邀请、备件与库存；只看自己订单范围内的工单；不能升级
- 配图：工厂视角工单详情（脱敏）+ 分销商视角工单列表

### P20 订单与协作邀请：接口人分三层
- 标题：组织级默认 + 订单级覆盖 + 工单级工程师
- 要点：每家工厂 / 分销商设组织级默认接口人（覆盖现在和以后全部订单）；个别订单可覆盖或排除；工厂接口人可在单张工单里再拉自家工程师，范围只限该工单
- 要点：订单新建 / CSV 导入（可接 ERP），序列号前缀与批次即时校验；邀请时可多选订单；缺接口人的订单标红并进"需要你的决定"
- 配图：订单页整屏 + 邀请弹窗（多选订单）

### P21 知识库管理：AI 回答客诉的依据，一张图看全
- 标题：产品线—知识条目—资料—零件—术语—缺口，连成一张会动的图
- 要点：产品是中心节点，条目按近 90 天命中次数变大，安全件带琥珀色环，资料按类型着色，解析中的会脉冲，缺口是虚线"!"；悬停看详情，点击跳到对应条目 / 资料 / 术语，选产品线整页随之过滤
- 配图：知识图谱面板整屏（全部产品线）+ 聚焦单一产品线（两张）

### P22 知识库四个页签
- 标题：资料进来、条目被用、术语统一、缺口有人管
- 要点：资料文件（上传说明书 / 爆炸图 / 3D 模型 / 历史客诉 / 故障码表 / 安装视频，自动识别类型与产品，解析入库）
- 要点：知识条目（多语言关键词、步骤、可寄零件、安全件标记、多语言回复模板、来源资料、近 90 天命中 / 解决 / AI 直接解决数）
- 要点：术语表（AI 填充小语种草稿并高亮待确认）；AI 缺口洞察（未匹配客诉、无资料产品、有资料无条目、缺 3D、缺合规字段、缺术语，每条带动作）
- 配图：四个页签各一张（2×2 网格）

### P23 产品与批次：客诉率按批次看
- 标题：哪一批货出问题，不用等客诉堆起来
- 要点：产品档案含合规字段；批次子表：批号、供应商、生产 / 首出货、出货量、订单数、客诉数、客诉率、二维码；异常标记"疑似批次缺陷"与"重点关注"
- 要点：从产品页一键进该型号的知识库、说明书任务、二维码；工厂角色只看自己供应的批次
- 配图：产品管理表展开 SM-900 批次子表

### P24 二维码管理
- 标题：一型号一码、按批次、按供应商，三档粒度随时切换
- 要点：生成可印刷的 SVG / PNG；预览 H5 落地效果；扫码次数、建单转化来自真实工单；扫码批次与序列号不一致时工单会提示
- 配图：二维码管理页整屏（可现场用手机扫屏幕）

### P25 数据分析与备件库存
- 标题：数据实时算，备货自动提
- 要点：数据分析：7 / 30 / 90 天切换，每日处理方堆叠（AI / 人工 / 工厂 / 门店），高频故障、渠道、语种、评分，一键周报
- 要点：备件与库存：备货建议由近 90 天故障推算；AI 承诺寄件与品牌方确认补发自动扣减；低于安全库存提醒；备货单下载
- 配图：数据分析页 + 备件库存页（左右）

### P26 系统设置：规则可管
- 标题：AI 什么时候能自己回、什么时候必须给人看，都是你定的
- 要点：政策面板：邮箱接入（可多个）、路由人与各级时限（影响 SLA）、置信度阈值（下方实时回放近 30 天"直答 / 追问 / 转人工"比例）、"先给人看"硬规则与触发词表、"可自动承诺"规则与金额线、H5 语种与外观
- 要点：每次修改记录谁在什么时候改了什么；关键项需技术与业务双签
- 配图：设置页政策面板（阈值回放 + 审计记录）

## 第四幕 · 说明书生成（5 页）

### P27 分幕页
- 同一个知识库，一边回答客诉，一边生成多语言说明书

### P28 为什么说明书和售后放在一个平台
- 标题：客户在 H5 看到的排障指引，和说明书里的是同一份
- 要点：说明书的排障章节、知识条目、术语表三者同源；产品管理里直接看到每个型号的说明书语种状态（已交付 / 生成中 / 待审核）
- 要点：说明书缺失或缺语种也是"缺口"，进知识库缺口洞察
- 配图：产品管理「说明书管理」列 + 知识库条目"来源资料"局部

### P29 三步向导与任务进度
- 标题：选型号、选语种、选市场，三步开始生成
- 要点：向导：型号 → 目标语种（可多选）→ 目标市场与模板；任务进度实时推进；智能体里一句"给 SM-900 生成德语和法语说明书"等价
