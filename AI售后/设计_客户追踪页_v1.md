# 设计 · 客户追踪页（邮件链接 H5）v1

> 2026-11-13。客户在售后邮件里点链接进入的 H5 页面：看到**自己邮箱名下全部工单**的实时进度。
> 产物：`原型_客户追踪页.html`（单文件，双击可开）；源码 `src/track_head.html` + `src/track_app.js`；测试 `src/tracktest.js`。
> 不改 `原型_品牌方后台.html` 与 `原型_H5扫码端.html`，也不跑 `build.py all`。

---

## 一、目标与边界

**要解决的**：邮件渠道的客户目前只能反复来信问"我的件寄了没 / 现在谁在处理"。FWT-61 里围绕"运单号/到哪一步"的往返占了 14 封邮件中的 4 封、拖了 4 天。这一页把**进度事实**（现在卡在谁手里、承诺哪一天、运单号多少）从邮件里搬到一个链接上，客户随时自看。

**边界（一期）**：
- 只读。客户回复仍走邮件（回复按钮 = mailto，带工单号进主题），符合"不改变海外用户发邮件的习惯"。
- 数据源是后台原型同一浏览器的 localStorage（`as_state`）＋ H5 收件箱（`as_h5_inbox`）。正式版接后端 + 签名短链 + SSE。
- 客户能看到什么 = 一条明确的**投影规则**（第三节），不是"把时间线原样丢出去"。

## 二、入口与身份

邮件里发的链接形如：

```
原型_客户追踪页.html?e=<邮箱>&k=<token>
```

- `e`：客户邮箱（URL 编码）。
- `k`：一次性/短期签名。原型用确定性哈希 `fnv1a(email.toLowerCase()+'|ironpeak-track-v1')` → 8 位 base36；正式版为 HMAC 签名、7 天有效、可吊销。
- `k` 不合法或缺 `e` → **过期链接页**："这个链接已失效，输入下单/来信时用的邮箱，我们给你发一封新的。" 输入后原型直接放行（模拟了发信），页面顶部标注"演示：正式版会等邮件里的新链接"。
- 只认 `cust.email`（小写全等）。**不做**模糊匹配、不按姓名匹配、不跨邮箱合并。命中不到任何工单 → 空态（见 5.4）。
- `?demo=1` → 演示用客户选择器（只列至少有 1 张工单的邮箱，带"进行中/已解决"计数，点击即以合法 token 进入）。**选择器只在 demo=1 时渲染**，正常链接路径不暴露他人的邮箱。

隐私：页面只显示掩码后的邮箱（`m***s@gmail.com`）；不渲染 `tr`、`confidence`、`reasons`、`kbId`、`suggest`、`capa`、`assignee/collab`、`pending.from` 等内部字段；不显示内部人员邮箱。

## 三、对客可见性投影（本页的核心）

后台时间线 `timeline[]` 的 `who` 有六种：`cust / ai / human / fact / dealer / sys`。一期邮件场景下真正"发给过客户"的只有两类：客户自己的原件（`cust`）和系统发出的回复（`ai`）。其余四类是内部协同记录（工厂原文 `fact`、人工内部备注 `human`、分销商打点 `dealer`、系统规则动作 `sys`），**一律不展示**。

例外处理：种子数据里个别 `ai` 条目其实是内部解析笔记，以 `(internal)` 开头或包含 `邮件解析：`。投影函数里用两条**结构前缀**判定（不是语义猜测）：

```
projectEvent(e):
  e.who==='cust'                         → {kind:'cust',   text:e.text}
  e.who==='ai' 且 text 不匹配内部前缀     → {kind:'ai',     text:e.text}
  其余                                   → null（不显示）
内部前缀 = /^\(internal\)/ 或 /^邮件解析[：:]/
```

**正式版**：写入时间线时就带 `aud:'cust'|'ops'` 字段（`addEntry` 增加参数），本页只读 `aud==='cust'`。原型不打乱后台数据，所以用上面的投影函数代替，并在「真/模拟」清单里写明。

**里程碑卡片不来自关键词，来自结构字段**（这些字段后台本来就字段化）：

| 里程碑 | 来源字段 | 条件 |
|---|---|---|
| 请求已提交 | `createdAt` | 恒有 |
| 助理已确认 / 首次回复 | 第一条可见 `ai` 事件的时间 | 有可见 ai |
| 转人工 | `statusSince` | `status==='human'` |
| 已升级工厂 | `statusSince` | `status==='factory'` |
| 修复指导窗口 | `guideDue` | `status==='guiding'` |
| 备件补发申请中 | `pending` | `pending && !shipped` |
| 承诺发出日期 / 已发出 / 运单号 / 已签收 | `shipments[].promisedAt / shippedAt / tracking / arrivedAt` | 逐条按存在性 |
| 已解决 | `resolvedAt` | `status==='done'` |
| 评分 | `rating` | `done && rating` |

**里程碑下的一句话概括（2026-11-16 补）**：每条里程碑标题下加一行情况描述，同样只用结构字段——首次回复用 `kbId`（条目类别 / 视频 / 可否随回复补发）+ `confidence`/`reasons`/政策阈值判定"给方案 / 追问 / 转人工"；已解决用 `resolvedBy`（ai / brand / factory / dealer）与是否有已签收寄件；寄件类用 `shipments[i]` 的 parts / method / to；备件申请用 `pending.part` 对应条目的 `partName`。实现见 `track_app.js` 的 `milestoneDesc()` / `replyKind()`，规则表在《原型v2说明》十·一。正式版这一句由 LLM 基于真实回复生成。

## 四、状态 → 对客文案

| 内部状态 | 客户看到的 | 处理中承诺 |
|---|---|---|
| `ai` | 助理处理中（AI 正在跟进，需要你会联系你） | 无 |
| `guiding` | 等你试一下（已给出修复步骤） | `guideDue` 前回访 |
| `human` | 售后工程师处理中 | `statusSince + policy routing.l1.hours`（默认 4 小时） |
| `factory` | 正在与工厂确认（不影响你这边的时间承诺） | `statusSince + routing.l2.hours`（默认 24 小时） |
| `done` | 已解决 | — |
| `late`（若存储） | 处理中（已超过承诺时间，正在加急） | — |

承诺时间从 `Policy.get('routing.l1.hours')` / `Policy.get('routing.l2.hours')` 实算（读 `adminState.policy` 覆盖值，与后台一致）；超时后文案转为"已超过承诺时间，正在加急"，不再显示倒计时。**只展示给客户一个宽承诺**，不暴露 SLA 内部等级（一级/二级）。

UI 语言：默认跟随当前工单的 `cust.lang`，chrome 文案支持 `en / de / zh`，其余语言回落 `en`（与 H5 的 sv/it 回落策略一致）；右上角可切换并持久化到 `localStorage['as_track_lang']`。消息正文永远原样显示，不翻译、不展示 `tr`。

## 五、页面结构

### 5.1 列表页（`#/`）

- 顶栏：品牌色圆点 + "IronPeak Support" + 语言切换 + "刚刚更新"微指示（4 秒轮询，数据有变化时闪现）。
- 问候区：`{名字或邮箱掩码}`，一句"这里是你名下的全部售后请求，进度会实时更新。"
- **进行中**分组（status ∈ ai/guiding/human/factory，按 `updatedAt` 倒序）：卡片 = 产品系列名 + 型号（`Smith Machine SM-900`）、问题摘要（`issue`，单行截断）、状态胶囊、最近更新相对时间、右侧箭头。若该工单有运单号，卡片上直接给"运单 879545895350"。
- **已解决**分组：默认收起（`已解决的请求 (N)`），展开后同款卡片但去色、显示评分星。
- 卡片底部一行：`工单 T-2610-0206 · 8 天前提交`。
- 只有一张工单时**不展示列表**，直接进 5.2 详情（单票据客户少点一次）。

### 5.2 详情页（`#/t/<id>`）

自上而下：
1. 返回（多工单时出现）+ 工单号等宽字体。
2. **状态横幅**（整宽、圆角、状态色底）：大标题产品名；一句"现在：售后工程师处理中"+"我们会在今天 18:40 前给你答复"（由 statusSince + 政策实算）；`guiding` 时是"试完请告诉我们结果，明天 10:00 前我们会来问"。
3. **进度轨道**（竖向，圆点+连线）：按四节里程碑顺序渲染实际发生与未来承诺；未来项灰虚线。
4. **寄件卡**（有 `shipments[]` 时）：件号清单原文、目的地、方式；四行小轨道 承诺 → 已发出 → 运单（等宽 + 复制按钮）→ 签收；未发生的行显示"— 等待中"。
5. **对话**（对客投影后的 `cust/ai` 消息，时间倒序无关、正序排列；客户消息右对齐品牌浅底，助理左对齐白底描边；为噪音控制，**默认只显示最近 6 条**，多出时"查看更早的对话 ▾"）。`cust` 消息若与 `issue` 重复（建单即抄送场景），不重复展示。
6. 评分（若有）。
7. 底部操作：`回复这封邮件`（`mailto:service@ironpeak.com?subject=Re: <工单号>`，正式版取该邮箱线程的 reply-to）与 `打开说明书`（链到 `原型_H5扫码端.html?m=<型号>`）；再下面若还有别的工单，列"你还有 N 个请求 →"。

### 5.3 过期链接页

标题"链接已失效"，说明 + 邮箱输入 + "发给我新链接"（原型直接进入并把该邮箱写进 URL；一行小字注明这是演示行为）。

### 5.4 空态

"这个邮箱名下还没有售后请求" + 两个动作：`去提交一个问题`（H5 链接）与 `回复任意一封我们的邮件`。若是 demo=1 进入的，附"演示客户选择器"入口。

### 5.5 演示选择器（`?demo=1`）

表格/卡片列表：邮箱（明文，demo 专用）、工单数、进行中数、示例产品；点击进入该客户的列表页。按"进行中数降序 → 工单数降序"排。

## 六、视觉规范

延续 H5 的令牌，不引第三方库、不引外链字体：

- 背景 `#F4F5F2`（比 H5 略暖，像信纸）；卡片 `#fff`、1px `#E5E8E2`、圆角 16（大卡）/ 12（内块）。
- 品牌色取 `settings.brandColor`（默认 `#0E7A6C`），`--brand-ink` 同 H5 的 -18% 暗化函数，`--brand-soft` 12% 透明。
- 正文色 `#171C22`，次要 `#6B7682`，极淡 `#9AA3AE`。
- 状态色：ai=`brand-soft/brand-ink`；guiding/human/factory=`#FBEEDC/#B7600A`；done=`#E6F2E6/#2F7D32`；late=`#FCEDEC/#B42323`。
- 字号 15 / 行高 1.55；标题 22（详情）/ 17（分组标题）；工单号与运单号 `font-variant-numeric: tabular-nums` + 等宽 `ui-monospace, "SF Mono", Menlo, monospace`。
- 最大宽 640px 居中，左右 18px；topbar sticky + `backdrop-filter: blur(12px)`，底色 `rgba(244,245,242,.86)`。
- 轨道：左侧 1px 线 `#DDE2DB`，圆点 10px（完成实心品牌色、当前 10px 实心+6px 外环、未来空心）；文字 13.5px。
- 动效：仅两处——状态横幅进入 180ms 上移淡入；数据更新时顶栏"刚刚更新"点脉冲一次。`prefers-reduced-motion` 全关。
- 无障碍：状态胶囊不单靠颜色（带文字）；复制按钮 `aria-label`；轨道 `role="list"`。

## 七、数据合并规则

1. 读 `as_state`（后台）→ `state.tickets`；读 `as_h5_inbox` → H5 记录（含尚未导入后台的）。
2. 合并键 `id`：后台工单为主；H5 记录若同 id，取 `updatedAt` 较新的状态，并把其 `transcript` 中超出后台已合并条数的尾巴以 `cust/ai` 事件补进来（与后台 `importInbox` 的 `h5Seen` 语义一致，但只读不写回）。
3. H5 记录后台没有的（客户还没等后台轮询）→ 映射为工单视图：`{id, product, sn, issue, status, createdAt, updatedAt, cust.email, timeline: transcript}`，列表里正常显示。
4. 仅保留 `cust.email` 小写等于 `e` 的；`email` 为空的 H5 记录不进入任何页面（除非 URL 的 `e` 为空且 demo 选择器里列出——不列）。
5. 排序：`updatedAt` 倒序；进行中永远在已解决之前。
6. 轮询 4s（与后台一致），并对 `window.storage` 事件即时响应；重渲染保留滚动位置与展开状态（用 hash + 模块内状态）。

## 八、真 / 模拟清单

**真的**：按邮箱精确取工单与合并 H5 记录；对客投影（内部事件不外泄，有断言）；里程碑与承诺时间由 `statusSince + Policy` 实算；运单/承诺/签收来自 `shipments[]`；多工单分组与排序；语言回退与持久化；token 校验（哈希）；复制运单；轮询更新；XSS 转义。

**模拟的**：token 是确定性哈希而非服务端签名（正式版 HMAC 短链）；"发新链接"不真发邮件；回复走 mailto 而非真实线程追加；"查进度"入口未回写到 H5 与后台邮件模板；跨设备/跨浏览器（localStorage 局限，与现有原型一致）；客户语言正文不翻译（按已有原文展示）；正式版 `aud` 字段在原型里用投影函数代替。

## 十一、实现后的修订（2026-11-13，视觉核对后）

**摘要优先用客户原文。** 首版列表卡片与详情"你告诉我们的"都用 `t.issue`，而种子数据里 `issue` 常是后台内部中文摘要（FWT-61 即如此），英文客户页面上出现整段中文。改为 `summaryOf(t)`：取对客投影后**第一条 cust 消息的第一行**（截断 140 字），没有 cust 消息才回落 `issue`。这样摘要天然是客户自己的语言，也与"不翻译正文"的口径一致。测试 8 增加断言：FWT-61 英文页面不出现中文内部标题、出现客户原句。

**未修的、已知的演示瑕疵**：FWT-61 寄件卡的件号清单与运输方式（"74 号件 ×1…"、"空运快递"）来自种子数据的自由文本，英文页面里照原样显示。正式版件号结构化（件号↔SKU）后按语种生成，原型不为此写翻译表。

**状态胶囊用短标签**：列表卡在移动宽度下完整句子会把产品名挤成省略号，胶囊改为短标签（Engineer on it / 工程师处理中），整句说明只放详情页横幅。

## 十二、P0 低风险增强（2026-11-16）

本轮只增强“状态是否真的变了”和“能不能顺手继续沟通”，不改变只读、邮件回复的产品边界，也不加入持续循环动效。

- **实时更新可见**：4 秒轮询除了刷新状态，还会比较当前工单结构与对客进度轨道；新增里程碑短暂着色并高亮一次，页面内出现“刚刚更新 · {进展}”，同时写入 `#announce` 的 polite live region。顶部 Live 标签只在变化后短暂变成“刚刚更新”，5.2 秒后恢复。
- **变化检测更完整**：`dataSig` 纳入 `statusSince / resolvedAt / guideDue / pending / timeline / shipments` 等结构字段；即使 `updatedAt` 没变，只要对客可见时间线出现新消息，也会触发更新提示。
- **滚动邮件回复条**：详情页滚过状态横幅后出现轻量固定回复条，滚到底部主按钮进入视口时自动让位；仍走原有 `mailto`，不新增页内发送。
- **键盘与语言**：语言按钮有稳定 id，切换后焦点回到原按钮；`<html lang>` 随 en/de/中文更新为 `en` / `de` / `zh-CN`。
- **可读性与触控**：`--muted` 改为 `#59646F`、`--faint` 改为 `#626D78`、琥珀/绿色状态文字加深；语言、复制、返回和“查看更早”等控件热区提升到 40–44px。
- **窄屏**：≤480px 顶部只保留 Live 圆点；≤360px 隐藏该圆点并压缩语言控件宽度；≤380px 列表卡的标题、状态胶囊改为分行，问题摘要最多两行，避免 320px 下互相挤占。
